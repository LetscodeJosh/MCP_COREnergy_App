3. How to Switch to Production Without Breaking the Workflow

Switching an enterprise healthcare profiling app between servers can often lead to authentication loops, schema crashes, or data loss. The MCP App includes four layers of automated fail-safes:

A. Automated Client-Side Protections

  • Automatic Session Cleansing on Domain Switch: In ApiService._restoreSavedSession(), the app inspects pims_active_base_url on boot. If it detects a change from development to production, it automatically purges the old development session cookie (sid). Users and MedReps will never be trapped in 401/403 authorization loops.
  • Autonomous Silent Re-Authentication & CSRF Renewal: If a production session expires in the field, the app silently authenticates via /api/method/login using secure stored credentials, retrieves fresh cookies and X-Frappe-CSRF-Token, and replays the user's action with zero UI interruption.
  • Zero-Data-Loss Offline SQLite Queue: All visits, engagements, and profiling records write first to local SQLite (DbHelper). If the production server is rebooting or undergoing DNS updates, all records remain safely cached and auto-sync in FIFO order upon reconnection.
  • Defensive Schema Sanitization: JSON deserializers use defensive null-coalescing and type coercion. If the production ERPNext server has additional custom fields or minor schema differences, the app ignores unknown properties without crashing.

B. Production ERPNext v15 Pre-Flight Checklist (Run Once on Prod)

Before launching to field reps on the production server, verify the following configuration on your production ERPNext v15 instance:

Target DocType Requirement Purpose / Impact if Omitted
COREnergy Engage Copy Add Custom DocPerm: Read, Write, Create for Employee - COREnergy, Next Level Manager - COREnergy, Field Force Manager. Prevents 403 Forbidden errors when field reps save or update hospital/clinic profiling data.
COREnergy Engage Add Custom Field: ownership_nationality (Data). Prevents 417 Expectation Failed errors during account profiling synchronization.
Unsuccessful COREnergy Engagement Add Custom Fields: unsuccessful_call (Check) and decision_maker_or_responsible_person_not_available (Check). Ensures geotagged unsuccessful visit logs with GPS coordinates are recorded without schema rejection.
